# Задача 1. Compare

## Контракт

Модули: `recursive_sorts.py`, `timed.py`.

* `mergesort(arr) -> list[int]` — рекурсивный mergesort, новый список.
* `quicksort(arr) -> list[int]` — рекурсивный quicksort (Lomuto, pivot =
  последний элемент), тоже возвращает новый список, вход не меняет.
* `@timed` — декоратор: после вызова в `func.last_time` лежит время в секундах
  (`time.perf_counter`).

## Объяснение решения

**Mergesort.** Делим массив пополам, рекурсивно сортируем половины, сливаем
два отсортированных списка за один проход. Стабилен, всегда одно и то же
дерево рекурсии глубины ⌈log₂ n⌉.

**Quicksort.** Partition (Lomuto): всё `≤ pivot` слева, остальное справа,
pivot встаёт на итоговое место. Рекурсия на левый и правый сегменты.
Pivot = `a[hi]`, на уже отсортированных данных партиции вырождаются.

**@timed.** Запоминает `perf_counter` до/после вызова, пишет разницу в
атрибут обёртки. `finally` фиксирует время даже при исключении.

**Корректность.** Mergesort: индукция по размеру + корректность `_merge`.
Quicksort: после partition pivot на своём месте, обе стороны содержат
ровно свои элементы → индукция сортирует весь массив.

## Оценка сложности

Пусть `n = len(arr)`.

| Алгоритм | Время (средн.) | Время (худш.) | Память |
|----------|----------------|---------------|--------|
| mergesort | `Θ(n log n)` | `Θ(n log n)` | `O(n)` на слитые копии + стек `O(log n)` |
| quicksort | `Θ(n log n)` | `Θ(n²)` (отсортированный вход) | стек `O(log n)` средн. / `O(n)` худш., плюс копия входа |
| `@timed` | `O(1)` сверх функции | — | `O(1)` |

## Визуализация работы алгоритма

`arr = [4, 1, 3, 2]`.

### Mergesort

```
[4, 1, 3, 2]
├─ [4, 1] → [4] + [1] → merge → [1, 4]
└─ [3, 2] → [3] + [2] → merge → [2, 3]
merge([1,4], [2,3]) → [1, 2, 3, 4]
```

### Quicksort (pivot = последний)

Идея одного **partition**: берём последний элемент как pivot, все `≤ pivot`
сдвигаем влево, сам pivot ставим на своё финальное место. Потом то же
рекурсивно слева и справа от него.

Старт: `[4, 1, 3, 2]`, pivot = **2** (последний).

Идём слева направо, `i`, это куда писать следующий маленький:

| смотрим | действие | массив | `i` |
|---------|----------|--------|-----|
| `4` | `4 > 2` — пропускаем | `[4, 1, 3, 2]` | 0 |
| `1` | `1 ≤ 2` — меняем с `a[i]` | `[1, 4, 3, 2]` | 1 |
| `3` | `3 > 2` — пропускаем | `[1, 4, 3, 2]` | 1 |
| конец | ставим pivot на `i` | `[1, 2, 3, 4]` | p=1 |

Pivot `2` уже на месте. Дальше только хвосты:

```
[1, 2, 3, 4]
 ├─ слева от 2:  [1]      → один элемент, готово
 └─ справа от 2: [3, 4]
      pivot = 4
      3 ≤ 4 → остаётся [3, 4], pivot на месте
      └─ слева: [3] → готово
```

Итог: `[1, 2, 3, 4]`.

### Почему время прилично отличается

На `list(range(3500))` у quicksort почти всегда `p = lo` (все слева пусто),
глубина ≈ `n` → квадрат. Mergesort делит пополам → линейно-логарифмически.
Тест `test_sorted_input_quicksort_slower_than_mergesort` поднимает
`sys.setrecursionlimit` (иначе `RecursionError`) и требует
`t_quick > 3 · t_merge`.
