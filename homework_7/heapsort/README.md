# Задача 3. Heapsort

## Контракт

Модуль: heapsort.py.

* heapsort(arr) -> list[int] — сортировка по возрастанию inplace.
  Без heapq, sorted(), list.sort(). Возвращает тот же объект arr.

Для эксперимента: mergesort_ref.py mergesort из hw 6;
compare_time.py — замер времён vs sorted() и mergesort.

## Объяснение решения

Heapsort работает в два этапа на max-heap (родитель ≥ детей):

1. Build-heap (_build_maxheap): алгоритм Флойда, sift_down от
   последнего нелиста к корню. За O(N) массив становится max-heap:
   в корне лежит максимум.
2. Extract-max цикл: для end = n−1 .. 1:
   * меняем arr[0] (текущий максимум кучи) с arr[end];
   * элемент на позиции end уже на своём месте в отсортированном хвосте;
   * уменьшаем размер кучи до end и просеиваем новый корень вниз.

После n−1 извлечений массив отсортирован по возрастанию.

Почему max-heap, а не min. Кладя максимумы в конец, хвост растёт
справа налево и получается возрастающий порядок без доп. массива.

Корректность. После build корень — максимум. Инвариант цикла: хвост
arr[end+1 .. n−1] отсортирован и содержит наибольшие элементы, префикс
arr[0 .. end] — max-heap из оставшихся. Обмен + sift_down сохраняют
инвариант, уменьшая кучу на 1.

## Оценка сложности

Пусть n = len(arr).

| Фаза | Время | Почему |
|------|-------|--------|
| build max-heap | O(n) | та же сумма \(\sum h/2^h = O(1)\) ⋅ n, что в Makeheap |
| n−1 × extract | O(n log n) | каждый sift_down ≤ O(log n) |
| итого | Θ(n log n) всегда | нет плохого pivot как у quicksort |
| доп. память | O(1) | inplace, итеративный sift_down |

Mergesort тоже Θ(n log n), но требует O(n) доп. памяти на слитые копии.
sorted() (Timsort) — O(n log n) с очень маленькими константами на C.

## Визуализация

arr = [4, 1, 3, 2].

**Build max-heap** (нелисты с i = 1, 0):

| шаг | массив | комментарий |
|-----|--------|-------------|
| старт | [4, 1, 3, 2] | |
| sift i=1 (1) | [4, 2, 3, 1] | 1 ↔ 2 |
| sift i=0 (4) | [4, 2, 3, 1] | 4 уже ≥ детей |

**Extract:**

| end | обмен | sift_down кучи [0:end) | массив |
|-----|-------|---------------------------|--------|
| 3 | 4 ↔ 1 | [3, 2, 1] + хвост [4] | [3, 2, 1, 4] |
| 2 | 3 ↔ 1 | [2, 1] + хвост [3, 4] | [2, 1, 3, 4] |
| 1 | 2 ↔ 1 | [1] + хвост [2, 3, 4] | [1, 2, 3, 4] |

Итог: [1, 2, 3, 4].

### Краткие выводы

1. Все три дают порядок Θ(n log n): время растёт примерно пропорционально
   n log n при увеличении n.
2. sorted() на порядок быстрее, так как реализация на C (Timsort) и меньше
   накладных расходов интерпретатора.
3. mergesort и heapsort на чистом Python близки, mergesort чуть
   быстрее на этих входах (меньше ветвлений / лучше локальность при merge),
   но heapsort выигрывает по памяти: O(1) vs O(n).
4. Heapsort нестабилен (равные ключи могут поменяться местами), в отличие
   от mergesort и Timsort.
