# Задача 1. Tracer

## Контракт

Декоратор `tracer` / `@tracer(file=...)` оборачивает функцию и при каждом
вызове печатает:

* вход в вызов: `-> name(args…)` с отступом `2 * depth` пробелов;
* после возврата: `<- name = result` с тем же отступом.

Глубина увеличивается на входе и уменьшается на выходе.
По умолчанию вывод идёт в `stdout`, параметр `file` нужен для тестов и логов.

## Объяснение решения

Декоратор держит счётчик `depth` в замыкании
и зеркалит этот стек в тексте:

1. перед вызовом — строка входа и `depth += 1`;
2. вызываем исходную функцию;
3. в `finally` — `depth -= 1`, затем строка выхода с результатом.

`finally` гарантирует корректный откат глубины, если внутри возникло
исключение. `functools.wraps` сохраняет `__name__` / docstring.

**Корректность визуализации.** Каждый вход увеличивает отступ ровно на один
уровень, парный выход печатается с прежним отступом. Вложенные вызовы
одной и той же обёртки разделяют один счётчик → дерево вызовов читается
слева направо / сверху вниз как настоящий стек.

## Оценка сложности

Пусть `C` — число вызовов обёрнутой функции, `A` — суммарный размер
`repr` аргументов и результата на один вызов.

| | Сложность | Почему |
|---|---|---|
| **Время** | `O(C · A)` сверх самой функции | две печати на вызов |
| **Память** | `O(1)` доп. (плюс стек рекурсии функции) | один счётчик в замыкании |

Сам декоратор не меняет асимптотику алгоритма, только добавляет I/O.

## Визуализация работы

Пример: факториал `fact(3)`.

```
-> fact(3)
  -> fact(2)
    -> fact(1)
    <- fact = 1
  <- fact = 2
<- fact = 6
```

Соответствие стеку:

| Момент | Стек вызовов | Печать |
|--------|--------------|--------|
| вход `fact(3)` | `[3]` | `-> fact(3)` |
| вход `fact(2)` | `[3, 2]` | `  -> fact(2)` |
| вход `fact(1)` | `[3, 2, 1]` | `    -> fact(1)` |
| выход `1` | `[3, 2]` | `    <- fact = 1` |
| выход `2` | `[3]` | `  <- fact = 2` |
| выход `6` | `[]` | `<- fact = 6` |
