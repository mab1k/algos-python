# Задача 3. Хеш-таблица

## Контракт

Реализован класс `HashTable` с операциями `put` / `get` / `delete`
(и `__setitem__`, `__getitem__`, `__delitem__`, `__contains__`, `__len__`).
Хранение — только `list` слотов. Встроенный `dict` не используется.

## Объяснение решения

### Как хранить данные

Один список `_slots` длины `_capacity` (степень двойки).
Каждый слот — одно из трёх:

- `None` — пусто (`EMPTY`);
- специальный маркер `_DELETED` — удалено (tombstone);
- `[ключ, значение]` — занято.

Ёмкость всегда степень двойки: так проще гарантировать полный обход
при двойном хешировании.

### Как разрешать коллизии: двойное хеширование

Открытая адресация: при занятости ячейки ищем другую в том же массиве.

1. `h1(key) = |hash(key)| mod capacity` — стартовый индекс.
2. `h2(key)` — шаг; всегда **нечётный** (взаимно прост с `capacity = 2^k`,
   поэтому последовательность обойдёт все слоты):
   `h2 = (|hash(key)| mod (capacity / 2)) * 2 + 1`.
3. i-я попытка: `(h1(key) + i * h2(key)) mod capacity`, `i = 0, 1, 2, …`.

Поиск идёт по этой последовательности. Встретили `EMPTY` — ключа нет
(дальше по цепочке его быть не может). `DELETED` пропускаем: цепочка
поиска не обрывается. При вставке первый `DELETED` можно переиспользовать.

**Корректность.** Ключ лежит ровно в одном слоте на своей probe-последовательности.
Сравнение ключей — по `==`, поэтому совпадение хеша ≠ совпадение ключей.
Пока `α` ограничен, средняя длина пробы мала.

### Что делать, если таблица заполнится

Смотрим долю занятых и tombstone-слотов:
`(size + tombstones) / capacity`. Если `≥ 0.75`, ёмкость удваивается,
все живые пары **перехешируются** в новый массив (`DELETED` отбрасываются).

### Инвариант

Ровно `_size` живых пар; у каждого ключа не больше одного слота;
пустые и удалённые слоты корректно различаются, чтобы поиск по probe-цепочке
не обрывался на tombstone.

## Оценка сложности

Пусть `n` — число элементов, `α` — коэффициент заполнения.

| Операция | Среднее (малый α) | Худший случай |
|---|---|---|
| `put` / `get` / `delete` | `O(1)` | `O(n)` (длинная проба) |
| `resize` | `O(n)` амортизированно | при удвоении |

При `α ≤ 0.75` среднее время основных операций — константа.
Память: `O(capacity) = O(n)`.

## Визуализация работы алгоритма

Нетривиальный пример из тестов: разные типы ключей
`put(1, "int")`, `put("1", "str")`, `put((1, 2), "tuple")`.

Ёмкость по умолчанию — 8. Индексы ниже — конкретный прогон
(`h1 = |hash(key)| mod 8`, `h2` — нечётный шаг по формуле из реализации).

| Операция | ключ | h1 | h2 | Проба | Что важно | Таблица (занятые слоты) | size |
|----------|------|----|----|-------|-----------|-------------------------|------|
| старт | — | — | — | — | — | все `∅` | 0 |
| `put(1, "int")` | `1` (int) | 1 | 3 | `1` свободен | пишем в 1 | `1: [1, "int"]` | 1 |
| `put("1", "str")` | `"1"` (str) | 3 | 7 | `3` свободен | **другой ключ**, не путаем с `1` | `1: [1, "int"]`, `3: ["1", "str"]` | 2 |
| `put((1, 2), "tuple")` | `(1, 2)` | 5 | 3 | `5` свободен | третий независимый ключ | `1: …`, `3: …`, `5: [(1, 2), "tuple"]` | 3 |
| `get(1)` | `1` | 1 | 3 | `1` → совпало | → `"int"` | без изменений | 3 |
| `get("1")` | `"1"` | 3 | 7 | `3` → совпало | → `"str"` | без изменений | 3 |
| `get((1, 2))` | `(1, 2)` | 5 | 3 | `5` → совпало | → `"tuple"` | без изменений | 3 |
