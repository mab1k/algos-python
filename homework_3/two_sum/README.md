# Задача 1. Two Sum

## Контракт

Решение — функция `two_sum(arr, k) -> tuple[int, int]`.
По условию пара существует ровно одна, функция возвращает индексы
в порядке возрастания. Формат вывода из условия (`"i j"` через пробел)
получается как `f"{i} {j}"`.

## Объяснение решения

Идём по массиву один раз и храним уже просмотренные значения в хеш-таблице
`значение → индекс`.

На позиции `i` с числом `arr[i]` проверяем, встречалось ли раньше
`need = k - arr[i]`. Если да — пара найдена: индекс из таблицы и текущий `i`.
Если нет — кладём `arr[i]` в таблицу и идём дальше.

**Корректность.** Пусть искомая пара — индексы `p < q`, где `arr[p] + arr[q] = k`.
Когда алгоритм доходит до `q`, значение `arr[p]` уже лежит в таблице
(оно было добавлено на шаге `p`). Тогда `need = k - arr[q] = arr[p]` находится
в таблице, и алгоритм возвращает `(p, q)`. Другой пары нет по условию,
поэтому ответ единственный. Элемент не образует пару сам с собой: мы ищем
`need` среди ранее сохранённых индексов, а текущий индекс ещё не записан.

## Оценка сложности

Пусть `n = len(arr)`.

| | Сложность | Почему |
|---|---|---|
| **Время** | `O(n)` | один проход; каждая операция с хеш-таблицей в среднем (амортизированная сложность) `O(1)` |
| **Память** | `O(n)` | в таблице не больше `n` пар |

## Визуализация работы алгоритма

Нетривиальный пример: `arr = [4, -2, 7, -4]`, `k = 0`
(положительное + отрицательное дают ноль).

| Шаг | `i` | `arr[i]` | `need` | Есть в `seen`? | `seen` после шага | Действие |
|-----|-----|----------|--------|----------------|-------------------|----------|
| 1 | 0 | 4 | -4 | нет | `{4: 0}` | запомнить |
| 2 | 1 | -2 | 2 | нет | `{4: 0, -2: 1}` | запомнить |
| 3 | 2 | 7 | -7 | нет | `{4: 0, -2: 1, 7: 2}` | запомнить |
| 4 | 3 | -4 | 4 | **да** (`0`) | — | вернуть `(0, 3)` |

Пара найдена: `arr[0] + arr[3] = 4 + (-4) = 0`.
